# Agent Loop 说明

## 1. 什么是 Agent Loop

`Agent Loop` 可以理解成 Agent 的工作闭环，它不是“问一次答一次”的固定流程，而是一个会自我推进的循环：

1. 先理解用户目标
2. 判断下一步要不要调用工具
3. 执行工具
4. 读取工具返回结果
5. 根据新的结果继续思考
6. 直到能够给出最终答案

一句话总结：`Agent Loop = Thought -> Action -> Observation -> 再次 Thought`。

## 2. 这个仓库里的 demo 做了什么

示例文件：`src/langchain/agent_loop_demo.py`

它模拟了一个客服 Agent，用户问：

`帮我看看订单 A1001 现在是什么状态，如果我要退款，是否符合规则？`

Agent 会分 3 轮完成任务：

1. 第一轮先查订单状态
2. 第二轮再查退款规则
3. 第三轮综合两次观察结果，输出最终结论

这个例子故意没有接入真实大模型，而是把“规划器”写成了规则逻辑。这样更适合学习，因为你能直接看到 Agent Loop 的骨架，而不是把关键逻辑都藏在模型黑盒里。

## 3. demo 的实现原理

### `DemoPlanner`

它扮演“大脑”的角色，负责决定下一步动作：

- 如果还没查订单，就先调用 `lookup_order`
- 如果用户问了退款，但还没查规则，就调用 `search_policy`
- 如果需要的信息都齐了，就进入 `finish`

### `TOOLS`

这里定义了两个工具：

- `lookup_order(order_id)`：返回订单状态
- `search_policy(keyword)`：返回退款规则

在真实项目里，这些工具通常会换成数据库查询、HTTP API 调用、知识库检索等能力。

### `AgentState`

它保存循环中的运行状态：

- `user_input`：用户原始问题
- `scratchpad`：每一轮的思考、动作、观察日志
- `observations`：每个工具的返回结果
- `final_answer`：最终答案

### `AgentLoopDemo.run`

这是整个循环入口。每一轮都做 4 件事：

1. 调用 `planner.plan(state)` 决定下一步
2. 如果是 `finish`，直接结束
3. 否则执行对应工具
4. 把工具结果写回 `state`，进入下一轮

这就是最典型的 Agent Loop。

## 4. 为什么这套结构重要

因为它把“推理”和“执行”拆开了：

- Planner 负责想下一步
- Tool 负责真正干活
- State 负责保存上下文
- Loop 负责把它们串起来

所以一个 Agent 才能处理多步任务，而不只是单轮文本生成。

## 5. 它和 LangChain / LangGraph 的关系

你现在看到的是一个“手写版 Agent Loop”。它的思想和 LangChain / LangGraph 里的 Agent 很像，只是框架帮你封装掉了很多细节。

对应关系大致是：

- `DemoPlanner` 对应 LLM + Prompt + 决策逻辑
- `TOOLS` 对应 LangChain tools
- `AgentState` 对应 graph state / messages / runtime state
- `run()` 里的 for-loop 对应框架内部的调度循环

也就是说，这个 demo 不是另起炉灶，而是在帮你把框架内部真正发生的事情“摊开看”。

## 6. 怎么运行

在项目根目录执行：

```bash
python src/langchain/agent_loop_demo.py
```

你会看到完整的执行轨迹，包括：

- 每一轮为什么这么想
- 调用了哪个工具
- 工具返回了什么
- 最后如何得出结论
